# Catsflow LINE連携 要件定義書

- 文書状態：方針確定／実装詳細は既存コード・実データ確認後に確定
- 更新日：2026-10-14
- 対象：LINE公式アカウント、LINE Mini App、Catsflowバックエンド、マネーフォワード MEデータ取り込み

## 1. 目的

LINEを主な利用窓口として、Catsflowの家計・予算・資産情報を確認できるようにする。マネーフォワード MEのデータを取り込み、Catsflowで集計・可視化・家計管理支援を行う。

## 2. 確定した方針

- フロントエンド：LINE Mini App（React + TypeScript）
- バックエンド：既存CatsflowのJava / Spring Bootを継続利用
- 開発用DB：既存のH2を利用する
- 独立した通常Webサイト：当面作らない。Mini App内で必要な画面を提供し、どうしても必要になった場合に追加する
- 初回ログイン・Catsflowアカウントとの連携：原則としてLINE Mini App内で完結させる
- LINE公式アカウント：コマンド、通知、CSV受け取り窓口として利用する
- LINEユーザーとCatsflowユーザーの紐付けは、クライアント入力のLINEユーザーIDをそのまま信頼せず、検証済みのLINEイベント情報とサーバー側の一時連携コードを照合して保存する
- 初期コマンド：`今月`、`予算`、`カテゴリ別`
- マネーフォワード ME連携：自動同期の可否を優先調査する。利用可能な公式取得手段が確認できない場合も、CSV取り込みを代替手段として用意する
- CSV受付経路は原則としてMini Appのアップロードを主経路とし、LINEトークでのファイル送信は補助経路とする（LINE側の制約により利用できない場合に限定する）
- 取り込み対象：家計簿の入出金明細に加え、資産推移データも対象とする
- CSVをLINEに送信した後の解析・検証・重複チェック・保存・結果通知は自動化を目指す
- 猫の経験値・レベル要素は段階的に追加する

## 3. 対象範囲

### 初期版の対象

- LINE Messaging APIのWebhook受信、署名検証、応答
- LINE Mini AppのReact + TypeScript画面
- Mini App内の初回ログイン・アカウント連携フロー（既存認証方式の確認後に実装詳細を確定）
- CatsflowユーザーとLINEユーザーの安全な紐付け
- `今月`、`予算`、`カテゴリ別`の問い合わせ
- マネーフォワード MEの入出金CSV取り込み
- マネーフォワード MEの資産推移CSV取り込み
- 取り込み後の重複排除・データ検証・結果通知
- 同期履歴、エラー、最終成功日時の記録
- 家計情報・資産情報をMini Appで確認する画面
- ローカル環境での開発・動作確認

### 初期版に含めないもの

- マネーフォワード MEの非公式スクレイピングやログイン自動操作
- 利用条件を確認していない非公開APIへの依存
- LINEからの支出登録・編集・削除
- AIによる自動分析・助言
- 定期レポートや予算超過通知の本格運用
- 本番公開・常時稼働環境の確定
- 本番DBの選定・移行
- 独立した通常Webサイト
- 口座別・銘柄別資産内訳の取得（取得元が提供し、取得可能と確認できる場合は別途拡張）

## 4. マネーフォワード MEデータ取得方針

優先順位は次のとおり。

1. Catsflowから利用可能な公式API・公式連携手段があるか確認する
2. 利用可能な公式手段が確認できた場合、利用条件・料金・取得可能データ・認証方式に沿って自動同期を検討する
3. 公式な自動取得手段が利用できない場合は、ユーザーがダウンロードしたCSVをLINE公式アカウントへ送信し、Catsflowが自動処理する方式を採用候補とする
4. LINEでのファイル受信仕様や制約が要件に合わない場合、LINE Mini App内のファイルアップロードを代替手段とする

CSV取り込み対象：

- 入出金履歴／月別家計簿CSV：日付、内容、金額、金融機関、カテゴリ、大項目・中項目、メモ、振替、IDなど、実際のCSVに含まれる項目
- 資産推移CSV：日付、合計、預金・現金・暗号資産、株式、投資信託、債券、FX、保険、不動産、年金、ポイント、その他など、実際のCSVに含まれる項目

資産推移CSVはカテゴリ別の時系列データとして扱う。口座別・銘柄別の資産内訳が含まれるとは想定しない。

CSVダウンロード機能はマネーフォワード MEのプレミアム会員向け。アプリ版・Web版でダウンロードできる範囲が異なるため、ユーザーが実際に取得できるCSVを確認する。公式案内：https://support.me.moneyforward.com/hc/ja/articles/49505374073497-%E5%AE%B6%E8%A8%88%E7%B0%BF%E3%83%87%E3%83%BC%E3%82%BF%E3%81%AF%E3%83%80%E3%82%A6%E3%83%B3%E3%83%AD%E3%83%BC%E3%83%89%E3%81%A7%E3%81%8D%E3%81%BE%E3%81%99%E3%81%8B

## 5. 技術・運用方針

- フロントエンド：React + TypeScript、LINE Mini Appとして提供
- バックエンド：既存CatsflowのJava / Spring Boot
- 開発用DB：H2
- 本番DB：永続化・同時利用・バックアップ要件を確認してから決定
- Webhook：LINE Messaging APIを利用する想定
- 開発中のWebhook公開方法：HTTPSトンネル等を別途選定
- ファイル受信・解析はコントローラーから分離したサービスとして実装する
- API取得とCSV取得は、可能な限り共通の正規化・保存処理を利用する
- Webhookイベントは `eventId` を保存し、再送処理の重複防止を行う
- CSV取り込みはヘッダー判定 → 必須列検証 → 値検証 → 重複判定 → トランザクション保存の順に実施する

## 6. セキュリティ・プライバシー要件

- LINEユーザーは連携済みの自分のCatsflowデータだけを参照できる
- LINEユーザーIDはクライアント入力を信用せず、検証済みのLINEイベントや信頼できる認証フローから確定する
- 連携コードを利用する場合は一時的・一回限りとし、有効期限を設ける
- Webhook署名を検証し、同一の `eventId` は再処理しない
- CatsflowユーザーとLINEユーザーの紐付けは専用の連携テーブルで管理し、本人確認済みのリンク情報だけを認可に利用する
- LINEチャネル情報、外部APIトークン等をソースコードへ直書きしない
- CSVはファイルサイズ、拡張子、文字コード、必須列、値を検証する
- CSVの内容をSQLやコマンドとして実行しない
- 同一ファイル・同一明細の再送で二重計上しない
- アップロードされたCSVは必要最小限の期間だけ保持し、原則として処理後に破棄する方針とする（保持要否は実装前に確定）
- ログにトークン、連携コード、明細メモ等の不要な個人情報を出力しない
- 連携解除と取り込みデータの削除・保持の扱いを定義する

## 7. 初期版の受け入れ条件

- Mini App内で初回ログイン・アカウント連携を行う設計が既存認証方式と整合している
- LINEから`今月`、`予算`、`カテゴリ別`に応答できる
- 他ユーザーの家計情報・資産情報を参照できない
- 対応CSVを受信またはアップロードし、自動検証・取り込み・結果通知ができる
- 同じCSVを再送しても二重計上しない
- 入出金CSVと資産推移CSVを区別して処理できる
- 取り込みに失敗した場合、原因を特定できる範囲の案内を表示し、内部情報は漏らさない
- 最終同期日時・最終成功日時を確認できる
- DB構造が未確認の段階で、未確認のテーブル名・カラム名を前提に実装しない

- 既存Catsflowの認証・ログイン方式とMini Appへの適用方法
- 現在のEntity、Repository、Service、DBスキーマと再利用範囲
- LINE Mini Appのチャネル・LIFF設定、認証方式、公開条件
- マネーフォワード ME向け公式API・公式自動取得手段の利用可否、規約、費用、取得範囲
- LINEトークでのファイル受信仕様・上限・イベント形式の確認。満たさない場合はMini Appアップロードを主経路にする
- 実際の入出金CSV・資産推移CSVのサンプルと文字コード・列の揺れ
- 重複判定キー、訂正・削除明細の反映方針
- 資産推移データの基準日、履歴の上書き・追加ルール
- 同期頻度、ファイル保持期間、失敗時の再試行
- 本番ホスティング、永続DB、バックアップ、費用
- 猫の経験値ルール、画面詳細、グラフの形式
