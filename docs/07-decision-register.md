# Catsflow 決定事項一覧

- 更新日：2026-10-16
- 目的：確定事項と未決事項を混同しないための記録

## 1. 確定

| ID | 項目 | 決定内容 | 根拠 |
|---|---|---|---|
| D-001 | アプリの主目的 | 長期的な資産形成を支援する | ユーザー方針 |
| D-002 | 月次評価 | 一定フォーマットで実施する | ユーザー方針 |
| D-003 | データ管理 | マネーフォワード ME中心＋Catsflowで手動登録・修正も可能 | ユーザー選択 |
| D-004 | 簿記 | 実用的な家計管理を優先。複式簿記は必須にしない | ユーザー選択 |
| D-005 | 投資管理（初期版） | Catsflowで銘柄名・毎月の投資額を設定し、MoneyForward ME資産推移CSVから投資信託全体の資産額を取得する。個別銘柄の評価額・損益・保有数量・取得単価は初期対象外 | ユーザー決定（2026-10-16） |
| D-006 | 負債 | 借金・負債を保持し、月次評価に含める | ユーザー方針 |
| D-007 | フロントエンド方針 | LINE Mini Appを主画面とし、独立した通常Webサイトは当面作らない | 既存設計書の方針。変更が必要なら別途判断 |
| D-008 | バックエンド | 既存Java / Spring Bootを継続利用する | 既存設計書・提供ZIP |
| D-009 | 開発DB | H2を利用する | 既存設計書・提供ZIP |
| D-010 | 取引金額の符号規約 | 支出は負数、収入は正数で保存する。集計時はtypeで収支判定し絶対値で合計する | 現行コード調査で一貫性を確認（08参照、2026-10-16） |

## 2. 仮決定・推奨案

| ID | 項目 | 推奨案 | 決定に必要な確認 |
|---|---|---|---|
| P-001 | 初期実装順 | 既存機能の安定化→データ整合性→資産・負債→月次評価→目標→投資積立計画・資産推移→AI | 現行コードとユーザーが最初に使いたい機能 |
| P-002 | AIの役割 | 数値計算はプログラム、AIは評価コメント・選択肢の提案を担当 | AIサービス、料金、UI |
| P-003 | AIによる更新 | 金融データ・目標の変更はユーザー承認後に確定 | 操作フロー |
| P-004 | 月次評価履歴 | 評価時点の数値・目標値・計算ルールを保存 | DB設計・保存量 |
| P-005 | データ出所 | 取引・資産・負債・投資情報に取得元と更新日時を記録 | 既存テーブルとの役割分担 |
| P-006 | 手動修正競合 | 再インポートで手動修正値を無条件上書きしない | 差分表示か優先順位か |
| P-007 | 投資入力 | 銘柄名・毎月の投資額はCatsflowで手動設定し、個別銘柄の保有情報は初期版で扱わない | ユーザー決定（2026-10-16） |
| P-008 | 純資産評価 | 資産と負債を別管理し、同一基準日で計算 | 資産・負債スナップショット設計 |
| P-009 | 猫要素 | 資産形成の継続・目標達成を補助する後続機能 | 経験値ルールとユーザー価値 |

| C-002 | 長期目標・達成予測 | 金額・期限・進捗と必要積立額を管理 | 追加予定候補 |

| C-004 | 生活防衛資金 | 生活費等を基に現金確保の目安を管理 | 追加予定候補 |
| C-005 | 生活プロフィール | 住居形態・生活費負担・今後の予定等を任意登録 | 追加予定候補 |
| C-006 | 将来シミュレーション | 積立・返済・収入・生活イベントの条件比較 | 追加予定候補 |
| C-007 | LINE通知・定期レポート | 月次案内・目標進捗・予算超過等を通知 | 追加予定候補 |
| C-008 | データ訂正・変更履歴 | インポート・手動修正・目標やプロフィール変更を追跡 | 追加予定候補 |
| C-009 | AI評価の根拠・データ充足度 | 使用数値・不足データ・実績と試算の区別を表示 | 追加予定候補 |

上記はユーザーが今後追加したい機能として候補化したもので、実装済み・初期版必須・詳細仕様確定を意味しない。優先順位・保存期間・画面/API/DBは未決定。

## 4. 未決定

| ID | 項目 | 未決の理由／決める前に必要な情報 |
|---|---|---|
| U-001 | マネーフォワード MEの自動取得 | 公式手段、条件、料金、取得範囲を確認する必要 |
| U-002 | CSVの厳密な形式 | 実際の入出金・資産推移CSVが必要。現行実装はISO日付・UTF-8前提のため、実CSVの日付形式・文字コードの確認が必要（08参照） |
| U-004 | 口座間振替の保存方式 | 片側／両側保存、関連付け、集計ルールが未確定。現行実装は振替列を未処理（08参照） |
| U-005 | 予算の保存先 | `schema.sql`に予算テーブルが存在しないことを現行コード調査で確認（08参照）。物理設計が必要 |
| U-006 | 負債の物理DB構造 | 現在のスキーマで専用構造を確認できない |
| U-007 | 投資商品・保有の物理DB構造 | 現在のスキーマで専用構造を確認できない |
| U-008 | 投資銘柄名の入力項目 | 銘柄名以外の識別コードを初期版で必要とするか未決定 |
| U-009 | 積立計画の補助項目 | 開始月・停止状態を初期版で必須とするか実装時に確認 |
| U-010 | 月次評価のスコア基準 | 数値・判定閾値を決める必要 |
| U-011 | AIサービス・料金・データ保持 | 具体的な利用方法が未決 |
| U-012 | 本番DB・ホスティング | 永続化、バックアップ、費用、運用要件が未決 |
| U-013 | Mini Appの実装状態 | 提供ZIP内にフロントエンド一式が見当たらない |
| U-014 | CSV一時ファイルの保持期間 | 個人情報・再試行要件を踏まえて決める必要 |
| U-015 | 猫の経験値・レベル | 資産形成への結びつけ方が未決 |
| U-016 | 生活プロフィールの項目・保持 | 任意項目、プライバシー、変更履歴、保持期間を決める必要 |
| U-017 | 生活防衛資金の算定方法 | 対象支出・対象資産・目安月数が未決 |
| U-018 | 目標達成予測・将来シミュレーション | 利回り等の仮定・シナリオの保存・不確実性表示が未決 |
| U-019 | 月次レビュー履歴の保存形式 | 評価時点の数値、目標、計算ルール、AIコメントの保存方法が未決 |
| U-020 | LINE通知・定期レポート | 通知種別、頻度、静音時間、停止設定が未決 |
| U-021 | データ変更履歴 | 既存の取込ログとの責務分担、保存対象・保持期間が未決 |
| U-022 | AI評価の根拠・データ充足度 | 表示方法と、根拠のない信頼度スコアを避ける基準が未決 |

## 4. 次に確定する順序

1. 現行コードの取引集計・CSV取り込み・認証の挙動
2. 実CSVの列と符号・振替・重複ルール
3. 手動修正と再インポートの競合ルール
4. 資産・負債・投資積立計画・目標の論理モデル
5. 物理DB設計と既存データ移行計画
6. 月次評価の計算式とテストケース
7. 初期版の画面・API・リリース範囲
