```text
今回の目的は、追加仕様を既存システムへ安全に反映するため、現状調査・仕様差分整理・実装計画を作成することです。

## プロジェクトの基本前提
- Java 21 / Spring Bootを利用する既存バックエンドを維持する。
- 既存のController / Service / Repository / Entity / DTO / Exception構成を優先し、重複実装を避ける。
- 現行DBスキーマ、初期化SQL、認証、ユーザー分離、既存データの扱いを先に調査する。
- 設計書の論理モデルを、そのまま物理DBへ機械的に追加しない。
- 既存機能を壊さない。既存コードの全面書き換えを避ける。
- 実装済み・一部実装・未実装・未検証を区別する。

## 今回の追加仕様
1. MoneyForward MEのWeb画面コピー＆ペーストによる資産情報取り込みを追加する方向。
2. 取り込み時は既存資産を照合して更新し、新規資産は追加する。全件削除・全置換は禁止。
3. 同じ資産の重複登録を防ぐ。資産名だけで安易に同一判定しない。
4. 取り込み前に解析結果のプレビューを表示し、ユーザー確定後に保存する。
5. 入力に存在しない資産を自動削除・ゼロ化しない。
6. 資産ごとに評価基準日・取得日時・取得元を保持する。
7. 各資産の最新有効値を使って純資産を評価する。評価日時の違いは隠さず、古いデータには一定期間経過後に警告する。
8. 長期負債は独立管理画面を持ち、生活プロフィールから遷移する。
9. 長期負債の基本項目は負債名・種類・月返済額・メモ。支払い終了予定日は任意入力。
10. 支払い終了予定日から残り期間は表示できるが、残債額や返済率を推測しない。予定日経過だけで自動完済にしない。
11. 固定費の登録・編集・管理を追加する。項目案はdocs/09にあるが、未確定部分を明示する。
12. AIによる情報登録・変更は、ユーザーに内容を提示して承認された後にのみ保存する。
13. ただし2026-11-15の既存方針では金融情報・生活プロフィールの外部AI送信を禁止している。AIサービス・データ送信方針が別途決まるまでは外部AI連携を勝手に実装しない。手動登録導線を維持する。

## 今回の作業フェーズ
まずは「調査と実装計画」だけを行ってください。コード・DB・設定ファイルを変更しないでください。

### 調査タスク
1. リポジトリのブランチ、作業ツリー、ディレクトリ構成、ビルド設定を確認。
2. 上記設計書を読み、今回の追加仕様と既存仕様の差分を一覧化。
3. 資産・資産推移・CSV取込・口座・負債・固定費・生活プロフィールに関係する既存コード、API、画面、DBテーブルを検索。
4. 既存のimport_files / sync_logs / webhook_events等の役割と、再利用可能な処理を確認。
5. 認証・ユーザーIDの取得方法と、他ユーザーのデータへアクセスできないことを確認。
6. 既存テストとビルドを実行し、成功・失敗・未実行を記録。
7. MoneyForward MEコピペ取り込みに必要な実データサンプルがリポジトリにあるか確認。なければサンプル不足として明記し、架空の形式を前提にパーサーを作らない。
8. 長期負債の残高項目が今回の登録フォームから外れている一方、純資産計算には残高が必要という設計上の論点を明示する。月返済額・終了予定日から残高を推定しない。
9. 資産鮮度の警告期間、資産識別キー、固定費項目、AI外部送信方針など未決定事項を一覧化する。

### 出力してほしい内容
次の見出しで調査レポートを作成してください。
1. 現状構成と主要ファイル
2. 追加仕様ごとの実装状況（実装済み／一部／未実装／未検証）
3. 既存DB・API・画面への影響
4. 既存設計書とコードの不整合
5. 未決定事項・ユーザー判断が必要な事項
6. 推奨する実装順序（小さな段階に分ける）
7. 段階ごとの変更対象ファイル候補
8. テスト計画・受け入れ条件
9. リスクとデータ移行・後方互換性への注意

## 実装時の禁止事項
- この調査フェーズではファイルを編集しない。
- ユーザー確認なしにDBスキーマや既存データを変更しない。
- 実データサンプルがない状態でMFコピー解析仕様を捏造しない。
- 未決定の鮮度日数・固定費項目・負債残高方式を勝手に決めない。
- AIサービスや外部APIへ金融情報・プロフィール情報を送信しない。
- 資産の欠損をゼロとみなさない。
- 資産名だけで重複判定しない。
- 既存資産を一括削除・置換しない。
- 支払い終了予定日から負債残高や返済率を算出しない。
- 既存の認証・ユーザー分離・テストを省略しない。

最後に、調査結果を提示して作業を止めてください。実装には着手せず、次の指示を待ってください。
```

## 実行時の注意
- リポジトリの作業ブランチを確認し、既存の未コミット変更を上書きしない。
- このプロンプトの初回実行では調査のみ。実装は調査結果をユーザーが確認した後に開始する。
