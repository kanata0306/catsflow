# Catsflow × マネーフォワード ME 連携仕様

- 更新日：2026-10-16
- 文書状態：連携方針は確定／取得手段・実CSV・競合ルールは未決定

## 1. 目的

マネーフォワード MEを家計データの主な取得元とし、Catsflowで長期評価に必要な情報を蓄積する。Catsflow内の手動登録・修正も許容し、取り込みデータと手動データの整合性を保つ。

## 2. 方針

1. 公式API・公式連携手段の利用可否、条件、料金、取得可能データを調べる。
2. 利用可能な公式自動取得手段が要件を満たす場合は自動同期を検討する。
3. 利用できない場合は、ユーザーがダウンロードしたCSVをCatsflowへアップロードする。
4. LINEトークでファイルを受信できるかは最新仕様・制約を確認し、未確認のまま前提にしない。必要ならMini Appアップロードを利用する。
5. 非公式スクレイピングや、利用条件が未確認の非公開APIには依存しない。
6. データの出所、基準日、最終更新日時を記録する。
7. 手動修正値を再インポートが無条件に上書きしない。
8. 同じファイル・同じ明細の再取り込みによる二重計上を防ぐ。

## 3. 対象データ

### 3.1 入出金履歴／家計簿CSV

公式ヘルプに記載された項目例として、日付、内容、金額、金融機関、大項目、中項目、メモ、振替、ID等がある。ただし実際の列名・文字コード・値の形式を確認し、サンプルを基準に対応する。

### 3.2 資産推移CSV

日付ごとの資産総額・カテゴリ別金額を対象候補とする。カテゴリ例は預金・現金、株式、投資信託、債券、FX、保険、不動産、年金、ポイント、その他など。実際のCSVに存在する列のみを処理する。

**初期版での利用範囲：** 資産推移CSVから、基準日・資産総額・「投資信託」カテゴリの金額（実CSVに列がある場合）を取り込む。Catsflowではこのカテゴリ全体の推移を保存・表示する。

**制約：** 口座別・銘柄別の評価額、保有数量、取得単価はこのCSVから取得できるとは想定しない。Catsflowの銘柄別積立計画と、CSV由来の投資信託全体の資産額は別データとして管理する。全体額を個別銘柄に按分しない。

## 4. 取り込みフロー（提案）

1. CSVを受信・アップロード
2. ファイルサイズ、拡張子、文字コード、ヘッダーを検証
3. 入出金CSV／資産推移CSVを判定
4. 必須列・日付・金額・値の形式を検証
5. 可能なら保存前に対象件数・エラー件数を表示
6. 外部ID等を用いて既存データと照合
7. 手動修正済みデータとの競合を確認
8. 取引は重複を除外して保存。資産推移は同一基準日の重複加算をしない
9. 成功・更新・スキップ・エラー件数を通知
10. 同期履歴と最終成功日時を記録
11. CSV一時ファイルは保持方針に従って削除

## 5. 重複・訂正の扱い

- 入出金CSVは外部IDがある場合に優先して照合する。
- IDがない場合の補助キーは、実データの一意性を確認してから決める。
- 同一CSVの再送で二重登録しない。
- CSVで既存明細の変更・削除を検出できるかは、出力仕様を確認して判断する。
- 振替明細は通常の消費支出と区別する。
- 資産推移CSVは日付と取得元を用いて同一基準日の追加・更新ルールを決める。
- 手動修正値があるデータを再インポートで無条件に上書きしない。競合時の差分表示・選択方法は未決定。

## 6. データ品質

保存することを検討する項目：
- 取得元
- ファイル名または同期方式
- 取り込み日時
- 対象期間・基準日
- 成功／一部失敗／失敗
- 読込件数・追加件数・更新件数・重複件数・エラー件数
- エラーの安全な概要
- 手動修正の有無・最終更新日時

## 7. 現状実装の確認メモ（提供ZIP）

- `CsvImportService` が存在し、CSVヘッダー検証・入出金明細の保存・同期ログ記録の処理がある。
- `schema.sql` に `import_files` と `sync_logs` がある。
- `CsvImportServiceTest` が存在する。
- 提供ZIP内のコードでは、入出金CSVの取り込み経路と資産推移CSVの完全な保存経路を同等の完成度とは判断できない。資産推移CSVの永続化は別途確認・実装が必要。
- 現在のコードは既定口座を選択して取引を登録する処理を持つ。口座・カードを正しく割り当てる方法は実CSV・既存データを確認して改善する。
- 現在のコードの金額符号・取引区分・重複判定・トランザクション境界は、長期資産評価に利用する前に検証する。
