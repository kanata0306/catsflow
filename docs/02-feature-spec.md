# Catsflow LINE連携 機能仕様書

- 文書状態：方針確定／既存実装とCSVサンプル確認後に詳細確定
- 更新日：2026-10-14
- 対象：LINE Mini App、LINE Messaging API、マネーフォワード MEデータ取り込み

## 1. 論理構成

1. LINE公式アカウントがメッセージやCSVファイルの受け取り窓口となる
2. LINE Mini App（React + TypeScript）が家計・資産の画面、初回連携、必要に応じたCSVアップロードを提供する
3. Spring Bootが認証・認可、コマンド処理、CSV検証、データ正規化、集計を担当する
4. 既存CatsflowのService／Repositoryを優先して再利用する
5. H2に開発データを保存する。本番DBは後続判断

独立した通常Web画面は作らない。Mini Appで実現できない要件が確認された場合に限り追加を検討する。

## 2. 初期LINEコマンド

| コマンド | 目的 | 応答内容 |
|---|---|---|
| `今月` | 当月の家計状況 | 当月支出、収入・収支（Catsflowで取得可能な場合） |
| `予算` | 予算の確認 | 予算額、使用額、残額、使用率（算出可能な場合） |
| `カテゴリ別` | カテゴリ別の支出確認 | カテゴリ名と当月支出額 |

共通ルール：
- 初期版のコマンドは参照のみとし、データの作成・更新・削除を行わない
- 前後空白を除去して判定する
- 不明なコマンドには利用可能なコマンドを案内する
- 未確認の項目は推測値を表示しない

## 3. Mini App内のアカウント連携

### 目標フロー

1. LINEからCatsflow Mini Appを開く
2. Mini AppがLINE側の認証状態を取得する
3. 未連携なら、Mini App内でCatsflowアカウントへのログイン／新規登録または既存アカウント連携を案内する
4. Spring Boot側で本人確認を行い、CatsflowユーザーとLINEユーザーを紐付ける
5. サーバーは一時連携コードまたは検証済みトークンを受け取り、専用の紐付けテーブルに保存する
6. 連携成功後、Mini Appのダッシュボードへ遷移する

### 連携ルール

- 連携時の本人確認はLINEプラットフォームの検証済み情報とCatsflow側のセッションを照合する
- クライアントから送られたLINEユーザーIDだけで連携済み判定を行わない
- 連携コードは一回限りで期限付きとし、失敗時または再利用時は無効化する
- 連携解除時は紐付けを削除し、以後の自動認可を停止する

### 必須ルール

- クライアントが送ったLINEユーザーIDだけで本人確認しない
- LINEプラットフォームのトークン等はサーバー側で検証する設計とする
- 既存Catsflowの認証方式を確認し、不要な認証機構を二重実装しない
- 他のCatsflowアカウントへの意図しない上書きを防止する
- 連携解除・再連携の仕様を定義する

※ LINE Login／LIFF／LINE Mini Appの具体的な認証構成は、LINE Developersの最新仕様と既存Catsflowの認証実装を確認して決める。

## 4. マネーフォワード MEとの連携方式

### 4.1 取得方式の優先順位

1. 利用可能な公式API・公式連携手段があるか調査する
2. 利用条件と取得可能データが要件に合えば、自動同期アダプターを実装する
3. 公式自動取得手段が利用できない場合は、CSVをLINE公式アカウントへ送信する方式を採用候補とする
4. LINEトークでのファイル受信仕様・制約が合わない場合、Mini Appのファイル選択・アップロードを主経路として使う

### 4.1.1 CSV受付経路

- 基本方針：Mini Appのアップロードを主経路とし、LINEトークのファイル受信は補助経路とする
- LINEファイル受信が制約に合わない場合は、Mini App経由のCSVアップロードへ切り替える
- ファイル種別はヘッダーと必須列により判定し、判定不能なCSVは保存せずエラーとする

非公式スクレイピング、MEのログイン情報をCatsflowに保存する方法、規約や利用条件が未確認のAPIには依存しない。

### 4.2 CSV種別

#### 入出金履歴／月別家計簿CSV

公式ヘルプで案内されている項目例：計算対象、日付、内容、金額（円）、保有金融機関、大項目、中項目、メモ、振替、ID。実ファイルの列名・文字コードを優先し、項目の有無に対応する。

#### 資産推移CSV

公式ヘルプで案内されている項目例：日付、合計（円）、預金・現金・暗号資産、株式（現物）、投資信託、債券、FX、保険、不動産、年金、ポイント、その他の資産。保有していないカテゴリは列に含まれない場合がある。

資産推移CSVは日付ごとの資産総額・カテゴリ別金額を保存する。口座ごとの内訳・個別銘柄の詳細を含むものとは想定しない。

公式ヘルプ：https://support.me.moneyforward.com/hc/ja/articles/49505374073497-%E5%AE%B6%E8%A8%88%E7%B0%BF%E3%83%87%E3%83%BC%E3%82%BF%E3%81%AF%E3%83%80%E3%82%A6%E3%83%B3%E3%83%AD%E3%83%BC%E3%83%89%E3%81%A7%E3%81%8D%E3%81%BE%E3%81%99%E3%81%8B

### 4.3 取り込みフロー

1. CSVをLINEトークに送信、またはMini Appからアップロード
2. ファイル形式・サイズ・拡張子・文字コードを検証
3. ヘッダーからCSV種別を判定（判定不能時はエラーにする）
4. 一時領域で読み込み、必須列・日付・金額・値の形式を検証
5. プレビューまたは件数サマリーを表示できる場合は確定前に提示する（初期版でプレビューを実装するかは未決）
6. 同一の `eventId` または同一ファイルを再送した場合は冪等に処理し、重複登録を防止する
7. 入出金CSVは外部IDを優先して重複判定し、Catsflowの既存明細と照合する
8. 資産推移CSVは日付と取得元をキーにスナップショットを追加・更新する
9. トランザクション内で保存し、失敗時は部分的な取り込みを防ぐ
10. 結果をLINEへ返信し、同期履歴を保存する
11. CSVの一時ファイルは設定した保持期間後に削除する。原則は処理後の破棄を検討する

### 4.4 重複・更新ルール

- 同じCSVを再送しても明細が二重登録されないこと
- 入出金CSVは外部IDを優先し、IDが欠ける場合の補助キーは実データ確認後に設計する
- 既存明細の変更・削除をCSVから検出できるかは列と出力仕様を確認して決める
- 資産推移CSVは同一日付のデータを単純加算しない。同一日付の再取り込みは上書きまたは同一データとして処理する
- 振替明細は通常の支出・収入と区別し、二重計上を避ける
- 「計算対象」や振替フラグを保持し、既存Catsflowの集計ルールと整合させる

### 4.5 取り込み結果通知

LINEへの結果メッセージ案：

- データ種別（入出金／資産推移）
- 読み込み行数
- 新規追加件数
- 更新件数
- 重複スキップ件数
- エラー件数と修正可能な範囲の説明
- 最終成功日時または資産データの基準日

詳細な明細メモや金融情報を通知文やログに不用意に含めない。

## 5. Mini App画面候補

- 初回案内／ログイン・アカウント連携
- 連携完了・失敗
- 家計ダッシュボード（今月の収入・支出・収支）
- 予算・使用率
- カテゴリ別支出
- 資産総額・カテゴリ別資産配分・資産推移
- CSVアップロード（LINEトークでのファイル受信を採用できない場合、または補助経路）
- CSV取り込み結果・同期履歴
- 猫の状態・経験値・レベル（後続）
- エラー・データ未登録案内

独立した通常Webサイトは初期版に含めない。

## 6. エラー対応

| 状況 | 方針 |
|---|---|
| 未連携ユーザー | Mini Appでの連携手順を案内 |
| 未知のコマンド | 利用可能なコマンドを案内 |
| 未対応形式・CSV判定不能 | 対応ファイルと確認箇所を案内し、保存しない |
| 必須列欠落・値不正 | 問題行・列を安全な範囲で案内し、原則ファイル全体を取り込まない |
| 重複明細 | スキップし、結果件数に含める |
| Webhook署名不正 | 処理しない |
| 外部取得失敗 | 既存データを壊さず、同期失敗を記録 |
| DB保存失敗 | トランザクションをロールバックし、再試行可能にする |
| 他ユーザーのデータへのアクセス | サーバー側の認可で拒否する |
