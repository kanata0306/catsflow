## 今回の更新

前回の投資機能の初期仕様を維持したうえで、ユーザーが将来的に追加したい機能候補を設計書に記録した。

### 投資機能の初期仕様（既存の決定を維持）

1. Catsflowでユーザーが投資銘柄名と毎月の投資予定額を設定する。
2. MoneyForward MEの資産推移CSVから、資産総額と「投資信託」カテゴリの資産額（実CSVに列がある場合）を取り込む。
3. 投資信託全体の資産額を基準日付きで保存し、月次推移を表示する。
4. 個別銘柄の保有数量・取得単価・取得原価・評価額・損益、売買履歴、配当・分配金は初期版の対象外とする。
5. 投資信託全体の資産額を銘柄別に按分しない。設定した月額は計画値であり、実際の買付実績や運用損益とはみなさない。
6. 実CSVに必要な列がない場合は推測せず「未取得」とする。

### 追加予定候補として記録した機能

- 純資産・資産構成の可視化
- 長期目標・達成予測
- 月次レビュー・改善履歴
- 生活防衛資金管理
- 生活プロフィール（例：実家暮らし、生活費の本人負担、今後の予定）
- 将来シミュレーション
- LINE通知・定期レポート
- データ訂正・変更履歴
- AI評価の根拠・データ充足度表示

これらは「追加予定候補」であり、実装済み・初期版必須・詳細仕様確定を意味しない。各機能の優先順位、画面/API/物理DB、保存期間は今後決定する。

## 注意事項

- 本書の論理モデルは既存の物理DB構造を確定するものではない。
- 既存実装や `schema.sql` を確認せずに新しいテーブル・カラムを実装しない。
- 未入力はゼロや「負担なし」と解釈しない。
- 実績値・ユーザー入力値・計算値・将来試算・AI解釈を区別する。
- 既存の `import_files`、`sync_logs`、`webhook_events` と将来の変更履歴の責務が重複しないよう、実装前に確認する。
